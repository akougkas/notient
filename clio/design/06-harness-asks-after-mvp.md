# Harness asks learned from the MVP

Input for the Clio Coder 0.6.3 team, mapped to NOTIENT.md work order A. These are capability requirements and compatibility questions, with no implementation sequence or competing sprint.
Extension evidence is pinned to `clio-mvp` commit `738e1bdf`; every relative file:line below is under `clio/notient-extension/`. Later admission and fix commits are outside this evidence snapshot.
The separately labeled gardener recipe evidence is from clio-design on 2026-10-12 and uses explicit repository-relative paths.
Host facts come from NOTIENT.md §2/§5/§7.6 and the released extension guide and authoring reference. Static implementation evidence is distinguished from live harness proof.
V20 and E1 through E10 remain extension fixes. None is transferred to the harness team by this note.

## A1. Admit runtime tools through the gateway

- Provide discovery and invocation of qualified runtime tools, required/optional agent admission, honest read/execute classification, explicit unavailable-runtime errors and a stable schema set across reload.
- Evidence: `clio-coder-extension.yaml:71` exposes search as a command child; `lib/command.mjs:25` parses one argv JSON payload per process; `runtime/extension.ts:33` registers only operator commands, observations and hooks. Stateful model calls currently have to leave the runtime.
- Classification must follow effects: `lib/write.mjs:359` makes command status recover writes, while `runtime/extension.ts:9` deliberately uses an observational snapshot. One name does not establish a read-only action.
- Resolve the package-wide read-class restriction before promising read-class retrieval in a stateful package. Search records served evidence at `lib/hybrid-search.mjs:62`; indexing writes SQLite and packs; Git runs at `lib/git.mjs:12`. Keeping the existing restriction requires execute classification here; a confined read facade would require an explicit isolation design. This compatibility choice belongs to the harness maintainer.
- Reuse the existing credential-free embedding service after admission and writable index storage are available. `lib/embedding-adapter.mjs:30` is the command HTTP workaround; `:79` is the deferred host adapter. E2 corrects its binding to the existing `context.embed({inputs, task, expectedProfileIdentity?})` contract; no replacement host embedding API is requested.

## A2. Register external roots as operator authority

- Provide exact canonical, digest-bound and revocable external-root grants, separate from package consent, with the same effective roots in Node permissions and the OS sandbox. Preserve the protected workspace/config/state exclusions in A2.
- Evidence: `bin/setup.mjs:175` stores application-owned registrations; `:183` writes absolute read roots into the source manifest, followed by reinstall instructions at `:186`. `clio-coder-extension.yaml:664` leaves runtime writes empty, so actual vault writes use unconfined commands.
- The external vault's `.git` must be writable under its grant. `lib/git.mjs:51` handles the normal index and `:12` invokes Git; access to Markdown alone cannot support journaled per-write commits and undo. The workspace `.git` must retain its existing protection.
- Make subprocess authority explicit as well. The current runtime has `exec:false` at `clio-coder-extension.yaml:666`; changing that boolean grants more than Git. A2 does not by itself answer whether the harness offers scoped execution or requires a separately consented broad exec grant.

## A3. Supply private durable extension storage

- Provide the `data` runtime root and host-owned `CLIO_EXTENSION_DATA_DIR` for command tools and hook commands, outside the digested package. Keep identity stable through update/reinstall/reload; deletion requires an explicit removal option.
- Evidence: `lib/config.mjs:19` chooses XDG state or packaged settings; `:68` places each SQLite index there. `bin/setup.mjs:177` creates index/journal directories and `:180` rewrites packaged settings. This host-specific path plumbing currently changes installation bytes.
- The directory must support SQLite WAL sidecars, separate writer exclusion, exclusive file creation, rename and fsync. `lib/index-lock.mjs:7` owns cross-process exclusion; `lib/vector-store.mjs:117` creates pack generations and `:143` selects WAL/FULL durability. The 1 MiB key-value store cannot replace these files.
- Runtime, command and worker views must resolve to the same private directory. Host storage identity does not replace extension locking, recovery or retention policy.

## A4. Export redacted memory with provenance

- Provide consented export of task-bank entries and applicable approved durable records, using the same redaction as handoff snapshots and preserving IDs, entry kind/class, text, injection counts and canonical repository/session provenance. Keep export separate from approval and prompt injection.
- Evidence: `runtime/extension.ts:37` only renders on session close. The current memory workflow passes recalled material through ordinary capture and revision calls, demonstrated by `test/memory.test.mjs:20`, `:29` and `:35`; those are fixtures, not an export service.
- `test/memory-workflow.mjs:12` validates supplied provenance and `:23` emits an unknown session when absent. Export must describe nullable/session-not-ready states explicitly so extensions neither invent identities nor refuse otherwise usable recall.
- Preserve the 2 s close observation budget and make the snapshot available early enough to durably spool it through A3. Model work and vault publication must not be required to finish inside session close.

## A5. Provide bounded model completion after a durable handoff

- Supply one host-owned completion mechanism with route policy, operator-turn priority, input/output and cost/deadline bounds, cancellation and explicit no-route behavior. Extensions must not need model credentials or a daemon for distillation.
- Evidence: `runtime/extension.ts:37` has no distillation dispatch; `lib/reminders.mjs:6` asks the conversational agent to record lessons. Automatic close-time distillation is deferred, not an implemented background service.
- A durable accepted-work receipt and observable completion/refusal are necessary to distinguish saved work from a terminated handler. `lib/journal.mjs:214` persists write intent, and `lib/write.mjs:294` resumes pending operations on a later command. These protect already-planned writes; they cannot recreate memory that the host never exported.
- The host must state its handoff durability and retry semantics; extension jobs still need idempotency. A5 supplies model execution, while A3 supplies bytes and A6 supplies a tool-capable worker lifetime.

## A6. Run admitted tools in headless and native workers

- Start a tools-only API 2 runtime when an admitted recipe requires it, with no UI, hooks or operator commands. Preserve the same root/data/service consent, action policy and qualified tool identities as attended execution.
- Evidence: `tools/status.mjs:5` is an executable command entry; `lib/command.mjs:25` is the shared process contract. The runtime at `runtime/extension.ts:33` remains a separate attended surface. `clio-coder run` can use the command path today, but cannot exercise those runtime hooks or services.
- A real worker receipt must identify package/envelope generation, admitted capability, effective confinement, cancellation and result. Headless command success must not be presented as proof of runtime-tool admission. A timer remains an external clock; A6 supplies neither scheduling nor broader unattended authority.

## A7. Treat argv payloads as data and expose named pane places

- Establish the released behavior of backticks, `$X` and `$(` inside extension/MCP JSON argv projections. Suppress shell-expansion-only rails for fixed argv execution while retaining payload path/rule policy. The September observation was on 0.5.1; this implementation has not established the 0.6.2 result.
- Evidence: `lib/command.mjs:27` accepts a single JSON argument; `clio-coder-extension.yaml:312` admits exact old/new Markdown text. Altering or escaping source prose to appease a nonexistent shell would violate the byte/revision contract. `lib/git.mjs:12` likewise uses an explicit executable argv.
- Provide consented named places bound to existing directories under declared read roots, usable by the read-only files pane without model-supplied free-form paths. Evidence: `runtime/extension.ts:25` falls back to a text panel and `clio-coder-extension.yaml:659` enumerates external vault roots; no registered-place integration exists yet.

## Additional contract gaps exposed by implementation

- **Capability class for tool-only workers, A1/A6.** Admit native workers whose complete authority is a required list of qualified extension tools, without requiring generic read/write/edit, a dispatch capability or an internal-helper label. Gardener evidence: `clio/notient-plugin/native/agents/notient-gardener.md:6` adds canonical read/edit only to pass workspace-edit policy; `:22` leaves them unused and requires a workbench-only host write boundary. The original seven-tool package validation failed with `workspace-edit agent 'notient-gardener' must require read and write|edit`. Released `src/domains/agents/spec.ts:351` imposes that rule, and `src/domains/safety/worker-permit.ts:240` refuses orchestration workers. Provide a headless path to declare and verify per-tool authority: generic edit confined to the workbench while explicitly admitted Notient commands retain their separately authorized vault roots. `run --agent --cwd` does not itself declare writeRoots (`src/cli/run.ts:601`); recipe validation is not proof that the combined confinement and command admission can run. This ask removes the manager-approved admission workaround without weakening the declared command boundary.
- **Schema `pattern` support, A1.** Provide a documented bounded pattern dialect consistently across validation, gateway invocation and authoring tools. Evidence: `clio-coder-extension.yaml:181` expresses requestId only by length; `lib/journal.mjs:8` and `lib/write.mjs:388` enforce the character rule after child startup, and `:391` checks the SHA-256 alphabet. The 0.6.2 schema validator refuses `pattern`; this was 02 review item 17, a design correction rather than an implementation defect.
- **Hook effect compatibility, A1/A6 authoring contract.** Publish one authoritative effect-by-hook-point table shared by types, validation, docs and the test host, with an actionable unsupported-effect diagnostic. Evidence: `lib/reminders.mjs:45` uses inject_reminder at turn_start, while `:50` uses annotate_tool_result at after_tool because inject_reminder is rejected there. Preserve those distinct semantics; no new after_tool reminder effect is required.
- **Lifecycle-capable test host, A1/A4/A5/A6.** Expose retained backing state, actual reload/resume/compaction transitions, middleware timeout/error policies and delivered-effect receipts. Evidence: `runtime/reminders.test.ts:84` creates a fresh host and `:86` manually transplants flags; `:40` asserts returned effects rather than their delivery. These simulations cannot establish live lifecycle persistence or pass-policy enforcement. The limitation was the stage 3 review's design correction.
- **Host-enforced operator setup, A2/A3.** Application setup currently has only the AI_AGENT presence guard at `bin/setup.mjs:69`; it exits before application reads, stdin or network. The secret path is `:52`, and setup later writes registrations and package files. This is a cooperative gate, not authenticated operator authority. Host-owned root/service administration needs the trust-authority prohibition at every autonomy level and must not delegate authority to editable environment variables.
- **Trusted invocation provenance, A1/A6.** Expose host-derived session, repository, worker/run identity and attended/headless context separately from model arguments. Evidence: `lib/write.mjs:31` enforces restrictions using caller-supplied authorization.origin and `:457` logs it. The declared operator/clio/unattended value is attribution, not authenticated permission. A future operator authorization grant must be bound to reviewed work; a host context label alone cannot prove human approval of a change.
- **One invocation deadline, A1/A5/A6.** Expose the remaining host deadline with cancellation and structured termination receipts across supported execution paths. Evidence: `lib/write.mjs:360` budgets 240 s locally, `lib/git.mjs:19` budgets subprocess time independently, and `lib/embedding-adapter.mjs:43` combines a configured timeout with an optional signal. E9 remains an extension fix; a host deadline would remove the need to reconstruct the enclosing timeout from manifest constants.
- **Frozen-schema visibility, A1.** Expose the active tool-schema generation/digest and a clear restart-required diagnostic when a package update changes it. Evidence: `clio-coder-extension.yaml:292` reserves all five revise modes, and `lib/embedding-off.mjs:27` implements the staged candidates placeholder. The MVP froze future fields early because reload cannot change a session's command-tool schema. Preserve that invariant rather than silently mixing generations.
- **Actual Node feature reporting, A1/A3/A6.** Report node:sqlite/FTS5 availability for the Node process that will execute each surface. Evidence: `lib/index.mjs:21` probes FTS5 instead of trusting a Node version, and `runtime/extension.ts:11` exposes degradation. A package must receive an honest capability result in attended and headless execution; it still owns its fallback behavior.
