1. **Move repair still changes authored code in two masking cases.** `clio/notient-extension/lib/move.mjs:155` and `:156` miss a root-level indented-code line consisting of one space, a tab and `[[One]]`, represented as `" \t[[One]]\n"`. The tab reaches column four, but neither check masks that line; the list-container ambiguity check at `:139` does not apply. Separately, `:170` treats an opening backtick as escaped whenever its immediately preceding character is a backslash. With two literal backslashes before an opening backtick, followed by `[[One]]` and a closing backtick, the backslashes escape each other and the link text is an inline code span. **Violates 02 §5's requirement to ignore indented and inline code, and §1's preservation of unrelated bytes.** Moving `One.md` to `Two.md` rewrites the literal example inside either code span. The final reparse uses the same masking logic and accepts the unintended changes. These are remaining cases beyond the fixed blockquote-fence and Obsidian-comment examples.

2. **Undo substitutes the recorded mode before checking for operator mode changes.** `clio/notient-extension/lib/undo.mjs:16` emits `final.mode` from the original journal record, although `clio/notient-extension/lib/write.mjs:551` collected the current file's mode. `clio/notient-extension/lib/git.mjs:111` then checks that substituted mode against HEAD. **Violates 02 §4's requirement that affected working files match their raw HEAD and stage-zero index blobs and modes before intent.** After a Notient replacement on a mode-0644 note, an unstaged operator `chmod +x` leaves the content unchanged. Undo passes preflight using the old mode and replaces the file with mode 0644, discarding the operator's mode change. Capture undo can similarly delete a note with a dirty executable bit. This is an already-dirty target, independent of the accepted final-check publication race.

3. **Inline-code matching crosses blank paragraphs and hides live references.** `clio/notient-extension/lib/move.mjs:173` searches the remainder of the document for a closing backtick, and `:175` masks the entire resulting span. **Violates 02 §5's tokenizer, complete incoming-reference repair and whole-move refusal clauses.** In ``"unmatched `\n\n[[One]]\n\n`\n"``, the backticks belong to separate paragraphs and do not form an inline code span around `[[One]]`. The implementation nevertheless masks the live reference. Moving `One.md` succeeds while leaving that reference dangling; the shared inverse scan can also miss a new reference that should block undo.

4. **Escaped closing brackets in reference labels are silently omitted.** `clio/notient-extension/lib/move.mjs:234` excludes every `]` from the definition label without recognizing escapes. **Violates 02 §5's normalized reference-definition resolution and refusal for unsupported or unlocatable link-bearing syntax.** The valid use `[go][a\]b]` and definition `[a\]b]: old/One.md`, separated by a blank line, produce no definition token. Moving `old/One.md` therefore succeeds without repairing this incoming reference. The inverse scan has the same omission. This is distinct from the ordinary multiline destination case that the fixes now handle.

5. **Markdown character references conceal real destinations from move repair.** `clio/notient-extension/lib/move.mjs:212` splits the raw destination at `#`, and `:319` decodes URI escapes without decoding Markdown character references. **Violates 02 §5's Markdown destination resolution and completeness requirements: repair the affected reference or refuse unsupported link-bearing syntax.** `[go](old/One&#46;md)` resolves to `old/One.md`, because `&#46;` encodes a period. The tokenizer instead records target `old/One&`, treats it as an unaffected ghost and permits a move of `old/One.md` that leaves the rendered link dangling. Reparse and inverse checks share the same incorrect interpretation.

6. **Replacement fallback still selects the dominant newline instead of the first newline.** `clio/notient-extension/lib/markdown.mjs:45` counts file separators and chooses the majority convention. **Violates the corrected 02 §1 rule:** when the matched span contains no separator, use the file's first separator, otherwise LF. For original bytes `"First\nSecond\r\nThird\r\nPhrase"`, replacing `"Phrase"` with `"New\nLines"` must insert LF, but the implementation inserts CRLF. `clio/notient-extension/test/revise.test.mjs:40` also describes and requires the incompatible dominant-style behavior. The matched-span conversion and bare-CR refusal are fixed; this fallback remains divergent.

7. **Capture deduplication follows moves that predate the capture.** `clio/notient-extension/lib/write.mjs:453` applies every committed, non-undone move whose source matches the candidate path, without establishing that the move belongs to the capture being examined. **Violates 02 §5's capture deduplication rule:** follow that journaled capture's committed moves and return a no-op when its live body still matches. Capture body A under name `N`, move it to `Archive/A.md`, then capture different body B under the same name on the same UTC date. The original inbox path is free and receives B. A later request for B follows A's earlier move when examining B's record, checks `Archive/A.md`, and misses the still-live B capture. It creates a duplicate and consumes quota instead of returning the required no-op and original receipt.

8. **Planning can exceed the aggregate Git deadline before the limiter sees it.** `clio/notient-extension/lib/git.mjs:96` runs preflight subprocesses through raw `git()` calls with individual timeouts. `clio/notient-extension/lib/write.mjs:603` measures the completed preflight, but passes that accumulated time to the adapter only at `:707`, after persisting an intent at `:705`. **Violates 02 §4's aggregate 60-second Git bound.** A move affecting about 100 existing paths executes roughly three Git subprocesses per path; individually successful 250 ms calls already exceed the aggregate limit before any aggregate check. Execution then persists an intent and fails on its exhausted budget. Undo verification at `clio/notient-extension/lib/write.mjs:498` similarly checks the accumulated budget only before a whole verification whose adapter allowance resets for each original operation, so the last verification can exceed the remaining aggregate allowance. The per-process bound does not establish the required per-operation bound, particularly on the Windows drive.

9. **Capture provenance still conflates contributor and authorization origin.** `clio/notient-extension/lib/capture.mjs:102` generates `created_by` from `input.authorization.origin`. **Violates 02 §5's capture construction clause:** always generate `created_by: clio`; record actual authorization origin independently in the journal, audit and commit. Operator and unattended captures instead write `"operator"` and `"unattended"`. This misattributes the capturing contributor and also changes capture plan hashes when only origin changes, because the incorrect value enters the generated note bytes.

10. **Capture accepts mapping objects as string tags.** `clio/notient-extension/lib/capture.mjs:80` extracts the remainder of each block-sequence item, and `:33` accepts an unquoted `key: value` as a string. **Violates 02 §5's requirement that existing capture tags be a list of strings.** Frontmatter `"tags:\n  - key: value"` is a sequence containing a YAML mapping. The frontmatter scanner accepts that ordinary mapping, and the tag validator passes it through unchanged instead of refusing it. A committed capture can therefore contain non-string tags despite the specified admission contract.

11. **Workspace filtering requires provenance fields that the contract does not require.** `clio/notient-extension/lib/capture.mjs:8` and `:13` return a searchable workspace only when `created_by`, `captured_at` and `workspace` all exist, with a parseable capture date. **Violates 02 §5's exact, case-sensitive frontmatter-workspace filter:** absence of the workspace property excludes a note; the clause does not restrict matching notes to complete capture provenance. An authored note containing `"---\nworkspace: repo\n---\nquartz\n"` is excluded from a search for `quartz` with `workspace: "repo"`, despite its exact matching workspace. The new field is present and filtering precedes ranking, but its admission rule silently hides valid matches.

12. **The frozen workspace schema has a different length bound.** `clio/notient-extension/clio-coder-extension.yaml:82` permits `workspace` strings up to 4096 characters; `clio/notient-extension/lib/index.mjs:221` applies the same bound. **Violates the literal amended `search.workspace` schema in 02 §5, which sets `maxLength: 255`.** Inputs of 256 through 4096 characters are accepted contrary to the published contract, leaving the session-frozen manifest and semantic validation inconsistent with the approved schema.
