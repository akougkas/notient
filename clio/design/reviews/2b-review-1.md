1. **Move repair can change authored code and comments.** `clio/notient-extension/lib/move.mjs:123` recognizes fences only after zero to three raw spaces, and `:133` masks only HTML comments. **Violates 02 §5’s move tokenizer and byte-preservation clauses:** ignore fenced code and comments and preserve unrelated bytes. When moving `One.md` to `Two.md`, a referrer containing `> ~~~\n> [[One]]\n> ~~~\n` has its valid blockquote code example rewritten to `[[Two]]`; `%% [[One]] %%` inside an Obsidian comment is also rewritten. The final reparse uses the same incomplete masking and accepts those changes.

2. **Live nested-list references are omitted from the move and inverse scans.** `clio/notient-extension/lib/move.mjs:129` treats every line beginning with four spaces as indented code. **Violates 02 §5’s complete incoming-reference repair and whole-move refusal requirements.** In the valid nested list `- parent\n    - [[One]]\n`, the child link is live Markdown, but its token is discarded. Moving `One.md` to `Two.md` succeeds while leaving the reference dangling. The inverse guard uses the same tokenizer, so a new incoming link in that position can also escape the required undo refusal.

3. **Valid multiline reference definitions are silently missed.** `clio/notient-extension/lib/move.mjs:199` limits destination parsing to the definition’s first line; `:109` accepts the resulting empty span. **Violates 02 §5’s reference-definition resolution and refusal for unlocatable destination spans.** For `[go][ref]\n\n[ref]:\n  old/One.md\n`, the parser records an empty destination and never associates the continuation with it. Moving `old/One.md` leaves the valid reference pointing to the removed path without a blocker. The same omission weakens the inverse’s new-reference check.

4. **Historical logs are inspected but omitted from dependency revision checks.** `clio/notient-extension/lib/move.mjs:426` and `:460` exclude every `Notient/Log/` file from the move and inverse read sets. **Violates 02 §2 recovery step 5, §3’s dependency recheck, and §5’s historical-log blocker and inverse-reference rules.** Only the current audit month is separately frozen as an affected file. If an operator adds `[[One]]` to an older monthly log after planning but before publication, the inventory of paths remains unchanged and no read revision catches the edit. The move can leave a broken historical reference instead of returning `AUDIT_LINK_BLOCKER`; an inverse can likewise miss a new reference to its disappearing destination.

5. **Structural recovery reads current note bytes before recognizing an already-published commit.** `clio/notient-extension/lib/write.mjs:168` calculates `allBefore` through `currentFile` before commit recognition at `:170`, even when the intent rows are already prepared. **Violates 02 §2 recovery step 3:** recognize a published candidate and finish eligible index/backlink/state repair without reclassifying later note edits. After a move publishes its ref and crashes, an operator save that makes the destination larger than 4 MiB causes `currentFile` to refuse before recovery reaches the recorded commit. The published operation remains unfinished despite its available candidate OID. This ordering was introduced by the structural-intent path.

6. **Suffix matches incorrectly defeat an exact vault-root match.** `clio/notient-extension/lib/move.mjs:295` adds all matching suffix paths to alternatives even after finding an exact root path; `:301` then declares ambiguity. **Violates 02 §5’s slash-containing wiki resolution order:** exact vault-root path first, then a unique suffix, with a different source-relative match also requiring refusal. With `old/One.md`, `deep/old/One.md` and root `From.md` containing `[[old/One]]`, the root and source-relative resolutions both identify `old/One.md`. The additional suffix candidate nevertheless blocks the move as `AMBIGUOUS_REFERENCE`.

7. **Batch-undo authorization includes operations that have already been undone.** `clio/notient-extension/lib/write.mjs:414` computes `hasMove` and the authority file set from all eligible originals before removing undone operations at `:455`. **Violates 02 §5’s selection of committed, not-yet-undone originals and authorization of the actual inverse write set.** In an operator vault, capture a note inside `Notient/`, move it outside that folder in the same batch, then undo the move. An unattended batch undo of the remaining capture affects only `Notient/` and selects no move, but the implementation refuses it because the already-undone move still participates in the authority check.

8. **The new structural plan hash binds attribution excluded by manager triage.** `clio/notient-extension/lib/write.mjs:525` adds `batch` and the full `authorization` object to the 2b structural hash. **Violates the updated 02 §5 planHash clause:** bind bytes, read set, inventory, HEAD, vault ID and operation while keeping request words, batch and origin out. Changing only attribution between a move or batch-undo preview and execution returns `PLAN_CHANGED` despite unchanged bound content. The new expectation at `clio/notient-extension/test/move-publication.test.mjs:110` also requires origin and request changes to invalidate the hash. This is the 2b-added behavior, distinct from the earlier 2a finding.

9. **Design correction required for an active batch with a zero aggregate content delta.** `clio/design/02-write-path.md:224` requires byte-identical plans to return `noop` without journal, audit or commit, while `:261` and `:262` require batch undo to create an inverse commit/log and mark originals undone. `clio/notient-extension/lib/undo.mjs:15` drops unchanged aggregate deltas, and `clio/notient-extension/lib/write.mjs:482` returns a no-op. For two still-active replacements `A → B` and `B → A` in one batch, this leaves both originals active without an inverse or backlinks, so they can continue blocking an earlier overlapping undo. The design must decide whether this batch produces an audit-only inverse that closes the originals or remains a no-op with active history. The current implementation follows one of two conflicting clauses; this is a design decision, not a Sol defect.

10. **Move commits omit their destination attribution.** `clio/notient-extension/lib/git.mjs:185` still emits literal `Notient-Destination: null` for every operation. **Violates 02 §4’s commit-message grammar for moves.** The newly enabled move record and audit line contain the destination, but the Git history trailer incorrectly declares none, preventing consumers of the specified commit metadata from recovering that destination directly.

block: authored code/comment changes, missed nested-list and multiline-definition references, omitted historical-log dependency checks, structural recovery before commit recognition, incorrect root-path ambiguity, authorization of already-undone batch members, and structural hashes that bind excluded attribution.
