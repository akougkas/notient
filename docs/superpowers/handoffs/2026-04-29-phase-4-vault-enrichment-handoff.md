# Phase 4 — Vault Enrichment Handoff

Date: 2026-04-29. Branch: `beta-spec`. Plan: `docs/superpowers/plans/2026-04-29-vault-enrichment-phase-4.md`. Spec: `docs/superpowers/specs/2026-04-29-vault-enrichment-data-model-design.md`.

## What shipped

- AST-aware writeback at `src/core/markdown/writeback.ts`: `applyApprovedLink({ target, heading?, block? })` and `applyApprovedRelation({ key, target })`. Pure parse → mutate AST → stringify via the shared unified pipeline. Idempotent (returns the same `source` reference when the edge is already present). Heading + block qualifier check is mutually exclusive.
- Pipeline (`src/core/markdown/pipeline.ts`) gained stringify handlers for `wikiLink`, `wikiEmbed`, `tagRef`, plus a paragraph/listItem wrapper that re-emits trailing `^block-id` markers. Round-trip is now byte-stable across wikilinks, embeds, block ids, and tag references.
- `daemon_write` DAL: `recordDaemonWrite({ noteId, sha, agent, targets })` returns `RecordId<"daemon_write">`; `findRecentDaemonWrite({ noteId, sha, withinSeconds = 5 })` returns `{ agent, targets } | null` for the most recent matching row inside the window. Cutoff is computed client-side; sub-second clock skew is tolerated and the doc comment names the assumption.
- Tier 1 cross-references `daemon_write` once per `runTier1` invocation. Wikilink and embed edges whose resolved target is in the row's `targets[]` get `source = '<agent>'` (e.g. `'linker'`) instead of the default `'wikilink' | 'embed'`. Frontmatter, tagged, contained_in, under_heading edges are NOT overridden.
- Tier 1 cleanup filter switched from `source IN [...]` to `class = 'EXTRACTED'` and from `WHERE in IN (SELECT VALUE id FROM block WHERE note = $note)` to `(in = $noteId OR in.note = $noteId)`. Both fixes are causally tied to the source-override behavior (re-runs on overridden edges no longer leak orphans).
- `ApprovalService` migrated to SurrealDB. `approveEdge({ id, table })` resolves source/target paths, runs the writeback, records `daemon_write`, atomic-writes the file, and records history. `rejectEdge({ id, table })` deletes the row. `reconcilePendingApplications()` replays in-flight writebacks at daemon start.
- **Failure-semantics contract: PENDING-STATE.** Every edge table now carries `applied: bool DEFAULT true` (added to `provenanceFields()` in `edgeTables.ts`). Approve flow flips `approved=true, applied=false`, runs writeback, then commits `history` + `applied=true` in one transaction. Crash recovery selects `approved=true AND applied=false` and replays from the writeback. The contract is documented at the top of `writeback.ts`.
- `history` table added to `schema.surql`. `HistoryService.record / getRecent / undo / undoLast / prune` all hit SurrealDB. Public API preserved (`HistoryRow.id` widened from `number` to `string` for the `RecordId`-derived form). Four inverters (`noteCreate`, `noteAppendSection`, `noteFrontmatter`, `noteMaturity`) use an injected `updateNoteSha(path, sha)` closure that issues `UPDATE note SET sha`.
- `nativeGraphBridge.ts`, `relatedSection.ts`, `frontmatterWriter.ts` and their tests deleted. The single live importer (`maturityAdvancer.ts`) inlined a private `upsertMaturityFrontmatter` helper that mutates `notient.vitals` + `notient.updated` via the `yaml` package. Kernel slot `nativeGraphBridge` removed.
- `echoGuard` shim deleted. ~20 consumer files cleaned (kernel slot, bootstrap registration, history inverters, chat tools, vitals service, conversation store, maturity advancer, agent tool bundle). Replacement is Tier 1's `daemon_write` lookup from above. `grep` returns zero matches for `echoGuard|EchoGuard|markEcho`.
- Awaken DAL at `src/core/awaken/awakenRun.ts`: `createRun`, `findCurrent`, `findLatestResumable`, `findById`, `updateStatus`, `subscribeToStatus`. Live query via `db.live(new Table("awaken_run"))` with per-runId filtering; `close()` calls `subscription.kill()`. At-most-one-active-run invariant is enforced by the CLI, not the DAL.
- Awaken worker at `src/core/awaken/awakenWorker.ts`: walks the vault sorted by priority globs, enqueues each note, awaits per-path completion (callback-first design with bus fallback), checkpoints every 10 notes, observes pause/cancel between notes via the live subscription. On `paused`/`cancelled`, the worker breaks the loop, persists final counters, and closes the subscription in a `finally`. On natural completion, terminal status is `completed` and never overwrites a paused/cancelled run.
- CLI control plane: `awaken --pause` / `--resume` / `--cancel` / `--status` plus shared `awakenSurrealClient` helper. `--pause`/`--cancel` exit 1 with stderr message when no run is active. `--resume` flips status to `'running'` and exits; the daemon's existing live-query subscription picks up the change. `--status` polls the run row at 1Hz and emits NDJSON until terminal.
- Per-vault TOML config at `src/core/config/configFile.ts`. `<vault>/.notient/config.toml` is read once at daemon start via `smol-toml`; deep-merge over `concurrencyDefaults`. Schema covers `indexer.{debounce_ms,concurrency,chunk}`, `awaken.{default_tier_filter,default_priority_globs}`, `surrealdb.{hnsw_cache_mib,log_level}`. Bootstrap threads values into embedder, extractor, indexer queue, chunker (per-call), and `surreal start` env. `notient init` writes a default file if absent.
- Search consumers fully on SurrealDB. `quick` strategy uses the `chunk_text` BM25 full-text index with `search::score(0)`. `balanced` uses HNSW kNN via `searchVectorWithPath` (default `EF=100`; bare `<|k|>` errors against materialised projections). `deep` is hybrid kNN + BM25 fused JS-side with weighted scoring (0.7/0.3). `graphExpansion` walks `wikilink WHERE approved AND applied`. The `vectorIndex` kernel slot, `EmptyVectorIndex` stub, and `hnswVectorIndex.ts` are deleted.
- Phase D1 handlers (`agentEvents`, `sessionGrant/List/Revoke`, `agentBrief`'s contradiction lookup) and the producers `agentEventStore` / `sessionGrants` query SurrealDB. Schema gained `agent_event`, `agent_session`, `agent_run` tables (each with a monotonic `seq` int so the wire-shape numeric id from the SQLite-era contract survives without AUTOINCREMENT).
- Phase 4 smoke at `src/daemon/__smoke__/phase4.smoke.test.ts` exercises (1) fresh awaken run, (2) pause-mid-flight + assert, (3) resume to completed, (4) approve linker proposal, (5) on-disk wikilink lands in `## Related`, (6) `daemon_write` row recorded with correct sha/agent/targets, (7) Tier 1 attribution `source='linker'` on re-save.

Test posture: 838 pass / 254 skip / 0 fail under `bun test`. `NOTIENT_SMOKE=1 bun run test:smoke` runs all four smoke files (17 pass / 0 fail across `surrealServer`, `tier1`, `tier23`, `phase4`).

## Known short-term gaps (Phase 5 owns these)

- **`daemon_write.sha` vs Tier 1 `bodySha` alignment.** Tier 1 hashes the joined-block text (post-AST), not the raw file body. The Phase 4 smoke wires `ApprovalService.hash` to compute the same Tier 1-equivalent SHA so the cross-reference fires. **Production wiring of `ApprovalService` must compute its `daemon_write.sha` the same way Tier 1 does**, or Tier 1 must record the file body SHA instead of the joined-block SHA. Both producers must agree. Pick one in Phase 5; the simpler fix is to have Tier 1 record the file body SHA (matches the watcher's hash) and update `daemon_write` writes accordingly.
- **`approvalService` is not yet kernel-registered in production.** Bootstrap omits the registration; consumers must construct their own instance. Phase 5 should register and call `reconcilePendingApplications()` on daemon boot.
- **`agent_run` table is defined but has no producer.** Coordinator still writes to SQLite. Phase 5 owns the Coordinator migration alongside `graph_nodes`.
- **`agentBrief` retains hybrid SQLite reads** for `notes.updated_at` (`lastTouchedAt`) and `graph_nodes` (claim/question collection). These migrate when Coordinator and the graph-node store move.
- **`InMemoryVectorIndex` survives in `src/core/indexer/vectorIndex.ts`** because `indexNote.test.ts` still constructs one. The class is harmless and unused outside that test; cleanup is a small follow-up.
- **`NotientSettings.nativeGraph`** (`writeRelatedSection`, `writeFrontmatterRelations`, `relatedSectionHeading`) is orphaned config kept untouched. Phase 5 settings cleanup can remove it.
- **Body-rooted wikilinks bypass the linker exclusion** (carry-forward from Phase 3). The `linkerNeighbors` query still excludes only via note-level traversals.
- **Tier 3 atomicity** (carry-forward from Phase 3). `runTier3` runs extractor + linker concurrently then writes; a partial failure can leave linker proposals without a `tier3_at` stamp.

## Footguns inherited (carry forward)

- HNSW is in-memory and rebuilt on startup. `SURREAL_HNSW_CACHE_SIZE` (now plumbed via `surrealdb.hnsw_cache_mib` in `config.toml`) bumps the cap.
- `<|k,ef|>` operator form is required for kNN against a cosine HNSW index when the projection materialises records. `searchVectorWithPath` always passes `EF`; bare `<|k|>` errors.
- DAL writes that touch `option<...>` fields must omit them when undefined; never pass `null`. `recordDaemonWrite`, `awaken_run` updates, `agent_event`/`agent_session` writes, `history.record` all follow this pattern via CONTENT-build conditionals.
- SurrealDB 3.0.5 SCHEMAFULL hard-rejects unknown fields. Only schema-declared keys may be written.
- `INFO FOR DB` table count is now 30 (was 26 before Phase 4): +`history`, +`agent_event`, +`agent_session`, +`agent_run`. The Phase 1 smoke harness was updated; future smokes that count tables should use the new number.
- `findCurrent` / `findLatestResumable` add `ORDER BY started_at DESC` so a deterministic row is returned even if the at-most-one-active invariant is ever violated by a buggy CLI.

## Phase 5 entry point

Phase 5 deletes the SQLite substrate: `src/core/db/database.ts`, `schema.ts`, `migrations.ts`, `graphStore.ts`, `hnswVectorIndex.ts`, the orphan `vectorIndex.ts` test consumer, and the `sql.js` dependency. New CLI verbs land: `graph dump`, `graph stats`, `links sync`, `links audit`, `backup`, `restore`, `nuke`, `migrate-vault`, `awaken --tier`, `reindex --tier`. Coordinator migrates to `agent_run`; `agentBrief` migrates off `graph_nodes` and `notes.updated_at`. The daemon_write SHA-alignment fix above ships as part of Phase 5's first commit so the Tier 1 attribution path works end-to-end without the smoke's hash shim.
