# Daily-use sprint — September 20, 2026

This is development after the September 17 public 0.1.0 release. It does not
change the release's historical acceptance claims. The terminal remains the
primary workspace, with Obsidian and visiting agents using the same note services.

## Changes

- **Evidence during a conversation.** Completed search and note-read results now
  populate the TUI's source cards before the final answer finishes. A call must
  match an observed tool invocation. Existing revision, quote, scope-derived
  result, deduplication and source-navigation rules still apply. Failed, malformed,
  stale, unpaired and previous-turn results do not become source cards. Opening a
  saved conversation continues to validate its recorded results.
- **Bound optional startup inference.** The vision probe now has a two-second
  budget, including time waiting for a reasoning slot. A stalled model leaves
  vision unverified for that daemon generation instead of preventing the local
  listener and pairing from becoming available. This is not full vision acceptance.
- **Find notes by filename.** Lexical and hybrid retrieval consider at most ten
  matching filenames from the already admitted index paths. Matches use complete,
  contiguous name tokens, rather than arbitrary substrings. Their results undergo
  live exclusion, scope and source-revision checks. Filename and body results use
  reciprocal-rank fusion, explicitly labelled as such rather than as BM25 scores.
  Quoted queries retain their existing exact body-phrase behavior. `context.get`
  receives the same revision-bound passages, never filename-derived quotations.
- **Authenticated evaluation.** The provider protocol evaluation tool now passes
  `NOTIENT_LLM_API_KEY` to the provider, allowing a private authenticated gateway.
- **Correct current documentation.** The plugin selection workflows and Pages
  deployment are distinguished from historical unfinished work. Embedding changes
  document the explicit Tier 2 rebuild needed when background AI is disabled.

## Owner-workspace observations

The experimental Windows vault is paired to the WSL daemon, with native editor
protection active, and the terminal workspace is open in Herdr. The reasoning
deployment uses the owner's selected full 262,144-token context and one Notient
reasoning slot. The authenticated replacement embedding route produced
768-dimensional vectors on synthetic inputs. The explicit embeddings-only rebuild completed all 896 admitted notes with zero
failures in about 11½ minutes. A subsequent semantic query returned five hits in
457 ms; all five source revisions and quotations matched the files. Background
pipeline policies remain disabled. All 964 Markdown files in the vault are
unchanged from the initial snapshot.

The first model-free baseline contains ten positive research questions and two
unknown-topic controls. Across that single pass, lexical retrieval took 11–704 ms
and bounded context retrieval took 10–310 ms. All 37 returned context passages
matched the recorded source revisions exactly. Eight of ten positive cases found
the expected note in the search results, and both controls returned no hits.
This is an initial operator-selected diagnostic set, not a calibrated relevance
evaluation or an answer-quality score. The filename change addresses one observed
miss: the repeat found nine of ten expected notes, with both controls still empty
and all 38 context passages exact. Repeat lexical latency was 13–936 ms and
context latency 12–664 ms while the full integration suite was running. The other
multi-term retrieval miss remains a follow-up. The plugin also reconnected after
the final daemon restart and successfully searched with editor protection active.

Chat inference did not establish readiness: the initial reasoning probe exhausted
its 300-second run budget without a completion, so the subsequent structured and
tool cases in that run never dispatched. Tiny follow-ups also timed out through
both the gateway and the direct provider. A later native-provider probe returned two output tokens in 22.3 seconds,
reporting about 0.11 output tokens/second and roughly 12 seconds to the first
token. This establishes extremely slow generation, not useful chat or tool-call
readiness. Catalog availability and a working embedding request must not be
reported as working chat or tool-calling capability.
Private deployment details and raw evidence remain outside the tracked documents.

## Acceptance and next work

Deterministic checks cover live source cards while an actual daemon's model
response is held pending, restored-source navigation and stale-source refusal,
startup with an advertised but stalled vision provider, filename-only retrieval,
and BOM/CRLF source preservation. Final verification: 2,666 unit tests and 543
integration tests passed, with zero failures. Type checking and the production
build passed. Lint reports zero errors and the existing 139 warnings. The Obsidian
plugin type check and build also passed. These are development-tree results, not
a new published release.

Remaining acceptance work is concrete: establish working reasoning and tool
calls on the chosen deployment; address the remaining multi-term retrieval miss;
then exercise the six N09 workflows together and collect
a real week of bounded discovery feedback. Neither a mocked model nor this short
session establishes that week of usefulness.
