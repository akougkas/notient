<task type="auto">
  <name>Task 1: Parallelize ChunkStore file loading</name>
  <files>src/services/chunkStore.ts</files>
  <action>
Refactor `loadAll()` to use `Promise.all()` with concurrency control instead of sequential awaits.

Current code (lines 133-151):
```typescript
for (const file of files) {
  if (file.endsWith(".json")) {
    const noteId = file.replace(".json", "");
    await this.loadNoteChunks(noteId);  // BLOCKING - waits for each file
  }
}
```

Replace with parallel loading:
```typescript
const CHUNK_BATCH_SIZE = 50; // Limit concurrent file reads
const jsonFiles = files.filter(f => f.endsWith(".json"));
const batches = this.chunkArray(jsonFiles, CHUNK_BATCH_SIZE);

for (const batch of batches) {
  await Promise.all(
    batch.map(file => {
      const noteId = file.replace(".json", "");
      return this.loadNoteChunks(noteId);
    })
  );
  // Yield to event loop between batches
  await new Promise(resolve => setTimeout(resolve, 0));
}
```

Add helper method:
```typescript
private chunkArray<T>(array: T[], size: number): T[][] {
  const chunks: T[][] = [];
  for (let i = 0; i < array.length; i += size) {
    chunks.push(array.slice(i, i + size));
  }
  return chunks;
}
```

WHY parallel: 542 files × ~10ms each = 5.4s sequential vs ~200ms parallel (with SSD).
WHY batching: Prevent file descriptor exhaustion and memory spikes.
WHY setTimeout(0): Yield to event loop so UI can render progress.

<task type="auto">
  <name>Task 2: Make IndexManager JSON parsing non-blocking</name>
  <files>src/services/indexManager.ts</files>
  <action>
The `loadIndexFromPath()` method does synchronous JSON.parse on potentially 300MB+ files (line 351).

Current code:
```typescript
const raw = await fs.promises.readFile(indexPath, "utf-8");
const data = JSON.parse(raw) as { ... };  // BLOCKS for 500ms+ on large files
```

Refactor to use streaming JSON parsing or chunked parsing:

Option A (Recommended - simpler): Use existing async loadFromDataAsync path
The HNSWVectorStore already has `loadFromDataAsync()` which is being used (line 416).
The issue is JSON.parse happens BEFORE that call.

Solution: Stream-parse the meta section first, then lazy-load docs:

```typescript
// Replace lines 350-351 with:
const raw = await fs.promises.readFile(indexPath, "utf-8");

// Yield before heavy parse
await new Promise(resolve => setTimeout(resolve, 0));

// Parse in next tick to not block
const data = await new Promise<ParsedIndexData>((resolve, reject) => {
  setTimeout(() => {
    try {
      resolve(JSON.parse(raw));
    } catch (e) {
      reject(e);
    }
  }, 0);
});
```

This isn't true streaming but yields the main thread before the heavy operation.

For true non-blocking, we'd need:
1. Split index into meta.json + docs.json (breaking change)
2. Use streaming JSON parser (new dependency)

The setTimeout approach gives UI responsiveness without breaking changes.

WHY setTimeout: Yields to event loop so Obsidian can render "Loading..." UI
WHY not streaming: Adds complexity, existing data format works with this fix

Emit progress events so UI can show loading status.

In ChunkStore.loadAll(), emit progress:
```typescript
async loadAll(): Promise<void> {
  const notesDir = this.storagePaths.chunksNotes;

  try {
    const files = await fs.promises.readdir(notesDir);
    const jsonFiles = files.filter(f => f.endsWith(".json"));
    const total = jsonFiles.length;
    let loaded = 0;

    // Use parallel loading with progress
    const BATCH_SIZE = 50;
    const batches = this.chunkArray(jsonFiles, BATCH_SIZE);

    for (const batch of batches) {
      await Promise.all(
        batch.map(async file => {
          const noteId = file.replace(".json", "");
          await this.loadNoteChunks(noteId);
          loaded++;
        })
      );
      // Emit progress (if kernel available)
      console.log(`[ChunkStore] Progress: ${loaded}/${total} chunks loaded`);
      await new Promise(resolve => setTimeout(resolve, 0));
    }

    console.log(`[ChunkStore] Loaded ${this.chunks.size} chunks from ${this.noteChunks.size} notes`);
  } catch {
    console.log("[ChunkStore] No existing chunks directory");
  }
}
```
