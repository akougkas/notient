## Terminology (Clarified)

| Term | Definition | ID Persistence | Storage |
|------|------------|----------------|---------|
| **Task** | User trigger (Quick Action click) | Ephemeral (runtime only) | None |
| **Insight** | Container: Actions + Suggestions + reasoning + context | Persistent | History logs |
| **Action** | Edit to a note (add tags, append section) | Persistent | Undo history + logs |
| **Suggestion** | Agent's idea (not yet applied) | Persistent | History logs |
| **Insight Stream 1-liner** | Summary displayed in Note Vitals | Own ID | UI state + logs |

## Two History Systems

### 1. Undo History (User-Facing Product)

**Purpose**: Allow users to reverse actions
**Scope**: Minimal - only what's needed to undo
**Stored in**: `actions/hot/current.json` (recent 200) + `actions/archive/`

```typescript
interface UndoRecord {
  id: string;           // Action ID
  timestamp: number;
  action: ProposedAction;
  undo: UndoPayload;    // Minimal reversal data
  status: "applied" | "undone";
}
```

### 2. Provenance History (Developer/Researcher)

**Purpose**: Full audit trail for debugging, research, AI improvement
**Scope**: Everything - context, reasoning, inputs, outputs
**Stored in**: `logs/` or intelligence DB

```typescript
interface ProvenanceRecord {
  insightId: string;        // The insight that produced this
  timestamp: number;

  // Full context
  trigger: {
    type: "quick-action" | "chat" | "workflow" | "auto";
    source: string;         // What UI element or automation
  };

  noteContext: {
    path: string;
    contentSnapshot?: string;  // Optional: note content at time
  };

  agentExecution: {
    agentType: string;
    prompt?: string;        // System prompt used
    modelUsed: string;
    tokensUsed?: number;
    durationMs: number;
  };

  reasoning: string;        // Agent's explanation

  outputs: {
    actions: ProposedAction[];
    suggestions: Suggestion[];
    insightSummary: string;
  };
}
```

## ID Ownership & Generation

### Principle: Generate at Point of Creation, Not Transit

| ID Type | Generated By | Format | When |
|---------|--------------|--------|------|
| Task ID | TaskQueue | `tsk_${uuid.slice(0,8)}` | On enqueue |
| Insight ID | Agent output processor | `ins_${uuid.slice(0,8)}` | When insight created |
| Action ID | Agent (inside Insight) | `act_${uuid.slice(0,8)}` | When action proposed |
| Suggestion ID | Agent (inside Insight) | `sug_${uuid.slice(0,8)}` | When suggestion created |
| Undo Record ID | ActionHistory | `rec_${actionId}_${ts}` | When action applied |
| Stream Line ID | InsightStream | `stm_${uuid.slice(0,8)}` | When displayed |

### Key Insight: Agents DO Generate Action IDs

**Why**: Actions need stable IDs for:
- Undo references
- Frontmatter annotations
- History correlation
- User can say "undo action X"

**Agents generate** → **Orchestrator tracks** → **History stores**

## ID Format Specification

### Standard Format

```
{type}_{random8}

type = 3 letters identifying the entity
random8 = first 8 chars of crypto.randomUUID()
```

### ID Types

| Prefix | Entity | Example | Persistence |
|--------|--------|---------|-------------|
| `tsk_` | Task | `tsk_12e561b8` | Ephemeral |
| `ins_` | Insight | `ins_7c3a4d5e` | Persistent |
| `act_` | Action | `act_9f1a2b3c` | Persistent |
| `sug_` | Suggestion | `sug_4d5e6f7a` | Persistent |
| `rec_` | Undo Record | `rec_act_9f1a2b3c_1736123456789` | Persistent |
| `stm_` | Stream Line | `stm_8a9b0c1d` | UI only |

### Derived IDs (for correlation)

```typescript
// Undo record ID derives from action ID
const recordId = `rec_${actionId}_${Date.now()}`;

// This allows: given an action ID, find its undo record
```

## What NOT to Change

1. **Task IDs** - Already ephemeral, correct
2. **ActionHistory storage format** - Keep for undo
3. **UI message IDs** - Stay UI-only (`user-${Date.now()}`)
4. **Chunk IDs** - Different system, don't mix
