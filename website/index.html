A place to think with your notes.

Notient is a calm terminal workspace over Markdown you own. Ask it something and every claim opens the exact passage it came from. Let it suggest a change and nothing moves until you have read the diff.

0.1.0 · the first public release, on GitHub. Early software with stated limits: Linux and WSL, local-model latency, and an Obsidian plugin that installs from a ZIP.

iHow it works

The notes stay yours. The models only visit.

One small daemon runs beside each vault. It reads your Markdown, keeps a structural and lexical index in a local database, and answers the terminal workspace, the command line, MCP agents such as Claude Code and Codex, an authenticated local HTTP API and an Obsidian companion plugin. They all reach the same operations with the same rules.

The index can always be rebuilt. Your approvals, rejections and change history cannot, so those are kept.

Answers carry their evidence

Ask, brief and compare return exact quotations bound to the saved revision they were read from. When the notes do not support an answer, Notient says so instead of reaching into the model's memory.

Changes wait for you

An agent, a pipeline or the in-app assistant can plan an edit, a move or an archive. It is stored as an exact before and after. Only a person applies it, and an edit you make in the meantime turns the plan stale instead of being overwritten.

Everything can be undone

Applied changes land in a journal with their original bytes. Undo is guarded: it refuses when you have written something newer, and it survives a restart halfway through.

Works before any model does

Reading, structure, links, tags and lexical search need no inference. Seven background workflows exist and every one of them is off until you turn it on.

A real run: finding a contradiction between two notes.

This is excerpted, otherwise unedited output from the Find contradictions pipeline, run on 17 September 2026 against a locally hosted qwen3.8-27b on two synthetic notes from the project's evaluation pack. It took 122 seconds, most of it reasoning. Both quotations resolved byte for byte in the recorded revisions, and the result was staged as a review, not written.

“Projects/Guarantee.md and Projects/Loss.md make incompatible claims about the same production cluster on the same date under the same failure condition. […] This is a direct contradiction rather than a temporal change or difference in assumptions.”

The same evaluation also recorded what went wrong: three of twenty-two runs exhausted their reasoning budget, and one synthesis joined two unrelated notes before its instruction was corrected. Those results are kept in the project ledger alongside the passes.

iiiData boundaries

Know exactly where a sentence of yours can travel.

Notient ships no hosted service and no telemetry. What leaves your machine depends on two choices that are yours, and they are separate.

BoundaryWhat crosses it
Local inferenceThe reference setup. Prompts and note excerpts go to an OpenAI-compatible endpoint on this machine or on a network you operate: llama.cpp, LM Studio, Ollama, vLLM and others.
A cloud endpointSupported when you configure one deliberately. That provider then receives the prompts, excerpts, images or embeddings Notient sends for inference.
An MCP hostA separate boundary. Claude Code, Codex or another host receives whatever note content its tool calls request and handles it under that vendor's policy, whichever model Notient itself uses.
Paired HTTPLoopback only, scoped credentials from a single-use pairing code, revocable at any time. Agents can ask for a review. They cannot approve one.

Note content is treated as untrusted data everywhere. Text inside a note can never grant a permission, approve a change or issue a tool command.

ivInstall

From the GitHub release.

You need Bun 1.4.2 or newer and SurrealDB 3.0.5 on your PATH. Linux and WSL are exercised; macOS is unverified on a real host and a native Windows daemon is unsupported. A model endpoint is optional.

# download, verify and install the release package
curl -LO https://github.com/akougkas/notient/releases/download/v0.1.0/notient-0.1.0.tgz
curl -LO https://github.com/akougkas/notient/releases/download/v0.1.0/SHA256SUMS
sha256sum --check --ignore-missing SHA256SUMS
bun add --global "$PWD/notient-0.1.0.tgz"

# or build from source
git clone https://github.com/akougkas/notient.git && cd notient
bun install --frozen-lockfile && bun run build && bun link

# guided setup: settings, one model endpoint, then a read-only health report
notient setup /path/to/your/vault

# open the workspace
notient --vault /path/to/your/vault

The Obsidian companion, version 0.1.0, is notient-obsidian-0.1.0.zip: extract its notient/ folder into .obsidian/plugins/ and pair it with notient pair create. It is not in the community directory.

Release v0.1.0 carries the package, the plugin archive, the OpenAPI document, installation notes and SHA-256 checksums. Those exact artifacts were verified from a clean install by bun run release:check. Notient is not on npm.
