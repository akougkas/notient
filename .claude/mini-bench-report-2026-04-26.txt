ARCHITECTURE NOTES
============================================================
  Nemotron-Cascade-2 is nemotron_h_moe — Mamba2/SSM + sparse attention hybrid (52 blocks,
    most SSM, some attention with 2 KV heads). 128 experts, A3.5B active. KV cache barely
    grows with context, which is why 1M ctx fits in 6.4 GB extra.

  Qwen3.6-35B-A3B is qwen35moe — hybrid SSM + full attention every 4 layers, 256 experts,
    8 active. The "qwen35moe" arch label in llama.cpp is shared across Qwen 3.5 / 3.6 since
    they use the same architecture; the GGUF general.name still reads "Qwen3.6-35B-A3B".

  Qwen3.6-27B is qwen35 — DENSE 27B, also hybrid SSM + attention every 4 layers, 24 attn
    heads, 4 KV heads (GQA 6:1). Bandwidth-bound at ~31 tps because all 26.9 B params get
    fetched per token (no MoE sparsity). Standalone bench confirms: 31 tps is the GPU's
    roofline, not a router config issue.

  gemma-4-26B-A4B is gemma4 — 128-expert MoE with 4B active, per-layer GQA (sliding-window
    pattern, head_count_kv array per layer). 16 attn heads, 30 layers. Lowest VRAM of the
    four, fastest TTFT (59 ms warm).


WHAT WORKED, WHAT DIDN'T (preset bug fixes applied)
============================================================
  [DEFAULT] -> [*]            : llama.cpp's preset parser only treats [*] as the global
                                cascade section. [DEFAULT] was silently ignored, dropping
                                jinja, flash-attn, cache-type-k/v, batch sizes, n-gpu-layers
                                from every model spawn.

  kv-unified = true added     : Without this, --ctx-size N + --parallel 4 splits the pool:
                                each slot gets N/4. With it, the pool is shared — a single
                                call can use the full N. Required for the user's "Nemotron
                                gets 500K, others get 262K" rule to actually mean per-call.

  Nemotron 524K -> 1M         : Trained context_length is 1048576. Hybrid arch keeps KV
                                growth small enough to fit (29.23 GB total).

  parallel=4 in preset        : Was already in the Nemotron section; no longer required
                                because n_parallel=-1 (CLI default) auto-resolves to 4 in
                                server.cpp:95-97 with kv_unified=true. Either way works.

  cont-batching = true        : Default is already true in common.h:515. The preset key
                                is redundant but harmless.

  flash-attn / q8_0 KV deltas : llama-bench shows essentially noise at 512pp/128tg. Both
                                start mattering at much longer contexts (KV memory pressure)
                                or with very long generation. Keeping them on globally is
                                safe and matches accepted best practice for AMD Vulkan.


USE-CASE RECOMMENDATIONS FOR MINI
============================================================
  Notient extractor (4 concurrent small chunks, JSON output):
      -> Nemotron-Cascade-2-30B-A3B
         187 t/s aggregate, 1.07 s effective per call, 138 ms warm TTFT.
         enable_thinking=false (Notient already does this).

  Long-context single conversation (> 256K input):
      -> Nemotron-Cascade-2-30B-A3B at 1M ctx (only model trained for it).

  Snappy chat / lowest first-token delay:
      -> gemma-4-26B-A4B (59 ms warm TTFT, 95 t/s gen, lowest VRAM at 20.6 GB).

  Highest-quality dense reasoning where speed is secondary:
      -> Qwen3.6-27B (31 t/s, but full dense 27 B params per token).

  Largest model with vision (mmproj):
      -> Qwen3.6-35B-A3B (35 B params, hybrid arch, 82 t/s gen, 4 GB KV at 256K).

  Daily orchestrator default:
      -> gemma-4-26B-A4B (current preload.sh choice). Fast TTFT, low VRAM,
         good headroom for swapping any of the others on demand.
